# Тренажёр из трёх заданий: Moodle + LTI 1.3

Версия Марии Шауловой (группа P4209) на основе каркаса лабораторной: три
собственных вопроса с короткими ответами по теме ВКР — аутентификация и
авторизация в веб-приложениях. `q1` спрашивает HTTP-заголовок для передачи
Bearer-токена (Authorization, 3 балла), `q2` — браузерный стандарт
беспарольной аутентификации по ключам (WebAuthn, 3 балла), `q3` — модель
контроля доступа по атрибутам субъекта/ресурса/контекста (ABAC, 4 балла).
Пустой ответ даёт 0 за вопрос. Пробелы по краям удаляются, регистр не
учитывается. Не строка, лишнее поле или ответ длиннее 200 символов
отклоняются как ошибочный запрос; готовый балл от браузера сервер не
принимает — правильные ответы хранятся только на сервере, в `src/grading.mjs`.

Проверено локально: `npm test` — 5 pass, 0 fail.

Приложение развёрнуто в Docker на собственном сервере (не Render), за
nginx-реверс-прокси с TLS-терминацией, сертификат Let's Encrypt для домена
`masha.gifts` выпущен 25.10.2026. Рабочий Moodle:
https://shmaria.moodlecloud.com/course/view.php?id=9 . Сервис:
https://masha.gifts . Открывайте тренажёр именно из элемента Moodle:
прямой переход на страницу приложения LTI-сессию не создаёт.

Основа проекта: Node.js 24+, ltijs 7.0.7, MongoDB 8.0, один процесс
приложения, отдельный HTTPS-домен и Moodle. Ни LRS, ни xAPI здесь не
используются. MongoDB хранит регистрацию LTI, ключи и попытки.

## Быстрый запуск (локально)

```bash
npm ci
cp .env.example .env
docker compose up -d mongo
npm test
```

Заполните `.env`: `PUBLIC_URL`, реальные адреса Moodle. Пока
`MOODLE_CLIENT_ID` пуст, приложение работает в режиме подготовки
регистрации. Затем:

```bash
npm start
```

## Развёртывание на сервере (как сделано здесь)

```bash
docker compose -f compose.server.yaml up -d --build
```

`compose.server.yaml` собирает приложение по `Dockerfile` и подключает его
к уже существующей сети реверс-прокси (`signal-tls-proxy_default`), чтобы
внешний nginx мог проксировать `https://masha.gifts` на контейнер
`lti-trainer:3000` без публикации порта наружу напрямую. MongoDB поднимается
отдельным контейнером `lti-trainer-mongo` с собственным volume.

Проверьте `https://masha.gifts/healthz`. Зарегистрируйте в Moodle инструмент
LTI 1.3 вручную (Site administration → Plugins → Activity modules →
External tool → Manage tools): URL инструмента `/lti/launch`, инициация
входа `/lti/login`, redirect URI `/lti/launch`, JWKS `/lti/keys`. Перенесите
полученные Client ID, Deployment ID и адреса платформы Moodle в `.env` на
сервере, пересоберите и перезапустите контейнер `lti-trainer`.

Разрешите сервис AGS для синхронизации оценок, приём оценок и создайте
элемент курса с максимумом 10 баллов и запуском в новом окне. Открывайте
его из Moodle под настоящей тестовой учётной записью студента, записанного
на курс.

## Задание студентам

Авторские вопросы и серверная проверка находятся в `src/grading.mjs`.
Идентификаторы `q1/q2/q3`, веса `3/3/4` и максимум 10 сохранены по
контракту лабораторной.

Базовое правило: в Moodle передаётся результат последней завершённой
попытки. Предыдущие попытки остаются в приложении. Повтор отправки
сохранённой попытки не создаёт новую попытку. Для каждой отправки
используется возрастающий серверный timestamp.

Браузер отправляет только `answers` и `requestId`. Пользователь, роли,
курс, ресурс и адрес строки журнала берутся из проверенного запуска LTI.
Сессия длится 45 минут; после перезапуска приложения необходимо снова
войти через элемент Moodle.

## Проверки и ограничения

`npm test` запускает четыре теста расчёта и один интеграционный сценарий.
Последний имитирует платформу, создаёт подписанный запуск, проверяет
OAuth-подпись и AGS, разделение студентов, запрет роли преподавателя,
подмену userId, replay nonce и повтор после сбоя. В тесте используется
тестовая память вместо MongoDB. Обычный запуск приложения всегда
использует MongoDB.

Не публикуйте `.env`, `data`, приватные ключи, id_token, ltik и cookies.
Не удаляйте MongoDB-данные во время работы: сменятся ключи инструмента и
потребуется обновление регистрации. Этот каркас рассчитан на один процесс
Node.js.
